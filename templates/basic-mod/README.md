# Hytale Devtools Mod Template

This project is generated by Hytale Devtools and gives you a ready-to-edit
Java mod with:

- a Gradle wrapper
- a VS Code launch config for the Hytale server
- IntelliJ run-config support through Gradle
- the Hytale Devtools companion mod wiring for schema exports and autocomplete

## Requirements

1. Install Hytale with the official launcher.
2. Install Java 25.
3. Optionally install IntelliJ IDEA if you want IntelliJ's Gradle and debugger tooling.

## Configure the Project

### 1. Project Name

Update `settings.gradle` if you want a different Gradle project name. This name
is used for the generated JAR in `build/libs`.

### 2. Gradle Properties

Review `gradle.properties` before you start:

- `maven_group` controls your Java package base.
- `version` is the mod version used during builds.
- `includes_pack=true` is the default because this template includes a sample asset-pack file.
- Change `includes_pack` to `false` only if you intentionally want a pure Java plugin with no asset-pack content.
- `patchline` should match the Hytale release channel you are targeting.

If Hytale is not installed in the default location for your OS, set:

`hytale.home_path=/absolute/path/to/Hytale`

Use forward slashes in that value so the same property format works cleanly
across platforms and tools.

### 3. Manifest

Update `src/main/resources/manifest.json` to match your mod. The most important
field is `Main`, which must point at your plugin entry class.

`Version` and `IncludesAssetPack` are refreshed from Gradle during builds so
they stay in sync with `gradle.properties`.

## Run in Development

### VS Code

Open the Run and Debug panel and run `Run Hytale Server`.

The generated launch config already includes:

- the correct `Assets.zip` path for the Hytale install detected when the mod was created
- the bundled Hytale Devtools companion mod for autocomplete/schema export features

### IntelliJ IDEA

Open the project as a Gradle project. The Gradle config also creates a
`HytaleServer` run configuration inside IntelliJ.

## Authenticate the Test Server

The first time you run the server you must authenticate it with Hytale:

1. Run `auth login device` in the server console.
2. Finish the browser/device flow with your Hytale account.
3. Optionally run `auth persistence Encrypted` so the server stays authenticated after restarts.

Never share the encrypted auth file.

## Build the Mod

Run:

`./gradlew build`

On Windows use:

`.\gradlew.bat build`

The built JAR is written to `build/libs`.

## Notes

- `run/` is disposable local server state and is ignored by Git.
- If you change Hytale install locations later, update `hytale.home_path` and the
  `hytale-devtools.customHytalePath` extension setting so Gradle and the VS Code
  launch config stay aligned.
- The template includes a sample recipe asset in `src/main/resources/Server/Item/Recipes/Example_Recipe.json` so the mod starts as both a plugin and an asset pack.
